🎯 What Are We Building?

We're building a To-Do List Application — a program that remembers tasks! You can add tasks, mark them as complete, and delete them. Unlike the calculator and converter which just do one-time calculations, this program stores data.

💡 What's Different About This Project?

The Calculator: Takes 2 numbers → Calculates → Shows result → Forgets everything

The To-Do App: Stores a list of tasks → Remembers them → Let's you add, update, delete

This is our first project with persistent data — information that stays around while the program runs!

📋 Your To-Do List:
0. [ ] Buy milk
1. [x] Walk the dog
2. [ ] Finish homework

📊 Understanding the Data Structure

Before we look at code, we need to understand how to store tasks. This is the most important concept in this project!

🤔 What Information Does Each Task Have?

Each task needs TWO pieces of information:

  1. task — The name of the task (e.g., "Buy milk")
  2. completed — Is it done? (True or False)
📦 Why a Dictionary?

A regular variable can only hold ONE value. But we need to store TWO things for each task!

A dictionary lets us store multiple values with labels (keys):

# One task as a dictionary one_task = { "task": "Buy milk", # Key: "task" Value: "Buy milk" "completed": False # Key: "completed" Value: False } # Accessing the values: one_task["task"] # Returns: "Buy milk" one_task["completed"] # Returns: False # Changing a value: one_task["completed"] = True # Now it's completed!
📋 Why a List of Dictionaries?

We have MULTIPLE tasks. So we put all task dictionaries inside a list:

todos = [ {"task": "Buy milk", "completed": False}, # Index 0 {"task": "Walk the dog", "completed": True}, # Index 1 {"task": "Finish homework", "completed": False} # Index 2 ] # Accessing: todos[0] # Returns: {"task": "Buy milk", "completed": False} todos[0]["task"] # Returns: "Buy milk" todos[1]["completed"] # Returns: True # The index (0, 1, 2) tells us WHICH task # The key ("task", "completed") tells us WHAT info about that task
⚠️ Indexes Start at 0!

In Python (and most programming languages), lists are 0-indexed:

  • First item = index 0
  • Second item = index 1
  • Third item = index 2

When the user wants to complete "Buy milk", they type 0, not 1!

🔧 Part 1: The Database Manager (backend_todo.py)

This file is like a database. It stores all tasks and is the ONLY file allowed to directly modify the data.

1. Creating the Data Storage (Lines 2-3)

Lines 2-3:

# Data storage
todos = []  # List
What's happening here?
  1. # Data storage — A comment explaining what this section is for.
  2. todos = [] — Create an empty list called todos. This will hold all our task dictionaries.

This is a global variable — it exists outside any function, so ALL functions in this file can access and modify it.

2. Adding Sample Data (Lines 5-12)

Lines 5-12:

def add_sample_data():
    """Adds sample data to the todo list."""
    global todos
    todos = [
        {"task": "Buy milk", "completed": False},
        {"task": "Walk the dog", "completed": True},
        {"task": "Finish homework", "completed": False}
    ]
Breaking it down:
  1. def add_sample_data(): — Define a function with no parameters.
  2. """...""" — Docstring describing what the function does.
  3. global todos — Tell Python we want to modify the global todos variable, not create a new local one.
  4. todos = [...] — Fill the list with 3 sample tasks so we have something to work with when the program starts.
🔑 The global Keyword

Without global todos: Python would create a NEW local variable called todos inside the function. The global one wouldn't change!

With global todos: Python modifies the existing global variable. All other functions will see the updated data.

3. Adding a New Task (Lines 15-20)

Lines 15-20:

def add_todo(task_name): # Cry
    """Adds a new todo item."""
    new_todo = {}  # Key => task, completed
    new_todo["task"] = task_name
    new_todo["completed"] = False
    todos.append(new_todo)
Let's trace through: add_todo("Cry")
  1. def add_todo(task_name): — Takes one input: the task name.
  2. new_todo = {} — Create an empty dictionary. Think of it as an empty box for our new task.
  3. new_todo["task"] = task_name — Put the task name inside. Now we have: {"task": "Cry"}
  4. new_todo["completed"] = False — New tasks aren't done yet! Now we have: {"task": "Cry", "completed": False}
  5. todos.append(new_todo) — Add this dictionary to the end of our list.
    • .append() is a list method that adds an item to the END.
✅ Before and After
# BEFORE add_todo("Cry"): todos = [ {"task": "Buy milk", "completed": False}, {"task": "Walk the dog", "completed": True}, {"task": "Finish homework", "completed": False} ] # AFTER add_todo("Cry"): todos = [ {"task": "Buy milk", "completed": False}, {"task": "Walk the dog", "completed": True}, {"task": "Finish homework", "completed": False}, {"task": "Cry", "completed": False} # ← NEW! Index 3 ]

4. Getting All Tasks (Lines 23-25)

Lines 23-25:

def list_todos():
    """Returns the list of all todo items."""
    return todos
The simplest function!

This just returns the entire todos list. The frontend calls this when it needs to display all tasks.

Why use a function? Instead of letting the frontend access todos directly, we use a function. This is called encapsulation — keeping the data "hidden" and controlled.

5. Marking a Task as Complete (Lines 28-32)

Lines 28-32:

def check_todo(index):  # index = 2
    """Marks a todo item as completed."""
    activity = todos[index]  # {"task": "Finish homework", "completed": False}
    activity["completed"] = True
    return True
Let's trace through: check_todo(2)
  1. def check_todo(index): — Takes the index (position) of the task to complete.
  2. activity = todos[index] — Get the dictionary at that position.
    • If index = 2, then activity = {"task": "Finish homework", "completed": False}
  3. activity["completed"] = True — Change the "completed" value to True.
  4. return True — Return True to indicate success.
🔗 Why Does This Actually Change the List?

When we write activity = todos[index], activity doesn't become a COPY of the dictionary — it becomes a reference to the SAME dictionary!

So when we change activity["completed"], we're actually changing the dictionary inside todos. They're pointing to the same object in memory.

todos[2] # {"task": "Finish homework", "completed": False} activity = todos[2] # activity points to THE SAME dictionary activity["completed"] = True todos[2] # {"task": "Finish homework", "completed": True} ← Changed!

6. Deleting a Task (Lines 35-40)

Lines 35-40:

def delete_todo(index):
    """Deletes a todo item."""
    deleted_item = todos[index]
    todos.pop(index)
    return deleted_item
Let's trace through: delete_todo(1)
  1. deleted_item = todos[index] — First, save the task we're about to delete (so we can tell the user what was deleted).
  2. todos.pop(index) — Remove the item at that index from the list.
    • .pop(index) is a list method that removes AND returns the item at that position.
  3. return deleted_item — Return the deleted task so we can display it.
⚠️ Indexes Shift After Deletion!
# BEFORE delete_todo(1): todos = [ {"task": "Buy milk", ...}, # Index 0 {"task": "Walk the dog", ...}, # Index 1 ← This gets deleted {"task": "Finish homework", ...} # Index 2 ] # AFTER delete_todo(1): todos = [ {"task": "Buy milk", ...}, # Index 0 (unchanged) {"task": "Finish homework", ...} # Index 1 ← Was index 2, now index 1! ]

After deleting, all items after the deleted one shift down by 1! "Finish homework" was at index 2, but now it's at index 1.

4. Displaying All Tasks (Lines 18-25)

Lines 18-25:

if choice == '1':
    todos = backend_todo.list_todos() 
    if not todos:
        print("No to-dos found.")
    else:
        for i, todo in enumerate(todos):
            status = "[x]" if todo["completed"] else "[ ]"
            print(f"{i}. {status} {todo['task']}")
This is the most complex display logic. Let's break it apart:
  1. todos = backend_todo.list_todos() — Get the list of all tasks.
  2. if not todos: — If the list is empty...
  3. for i, todo in enumerate(todos): — Loop through the list. enumerate() is special — it gives us BOTH the index AND the item!
  4. status = "[x]" if todo["completed"] else "[ ]" — A ternary expression:
    • If completed is True → show "[x]" (checked)
    • If completed is False → show "[ ]" (empty)
  5. print(f"{i}. {status} {todo['task']}") — Display the task with its index and status.
🔢 What is enumerate()?

Normally, a for loop gives you just the item:

# Normal for loop: for todo in todos: print(todo) # {"task": "Buy milk", "completed": False} # But we don't know the index!

enumerate() gives you BOTH the index AND the item:

# With enumerate: for i, todo in enumerate(todos): print(i) # 0 print(todo) # {"task": "Buy milk", "completed": False} # Now we know the index!

We need the index so users can say "Complete task 2" or "Delete task 0".

6. Completing a Task (Lines 32-40)

Lines 32-40:

elif choice == '3':
    try:
        index = int(input("Enter index to check: "))
        if backend_todo.check_todo(index):
            print("To-Do checked successfully.")
        else:
            print("Invalid index.")
    except ValueError:
        print("Please enter a valid number.")
Why try/except?
  1. index = int(input(...)) — We need to convert the user's input to an integer.
  2. Problem: If the user types "banana", int("banana") fails!
  3. try: — Try to do the dangerous conversion...
  4. except ValueError: — If it fails, catch the error and show a nice message.
🔄 The int() Function

input() always returns a string. Even if the user types "42", Python sees it as the text "42", not the number 42.

user_input = input("Number: ") # User types: 42 print(type(user_input)) # ← It's a string! # To use it as a number, we must convert: index = int(user_input) # Now it's an integer print(type(index)) # ← Now it's a number!

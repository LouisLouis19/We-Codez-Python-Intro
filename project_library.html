🎯 What Are We Building?

We're building a Library Management System — a program that lets you manage books just like a real library! You can add new books, see all books, borrow books, and return them.

📖 Real-World Analogy: The Library

Think of this program like a real library:

  • The Bookshelf (our data) — This is where all the books are stored. Each book has a title, author, and information about who borrowed it.
  • The Librarian (backend_library.py) — This is the person who manages the bookshelf. They add books, track who borrowed what, and organize everything. The librarian knows ALL the rules about books.
  • The Front Desk (library_app.py) — This is where you (the customer) interact. You tell the front desk what you want, and they communicate with the librarian behind the scenes.
🧠 Why Two Files?

We separate the code into two files for organization and reusability:

File Role What It Does Uses print/input?
library_app.py Frontend (User Interface) Shows menus, asks for input, displays results ✅ YES
backend_library.py Backend (Logic & Data) Stores books, handles borrowing/returning logic ❌ NO

📊 Understanding the Data Structure

Before we look at the code, let's understand how books are stored. This is the most important concept in this project!

📚 What Information Does Each Book Have?

Each book needs to store 4 pieces of information:

  1. title — The name of the book (e.g., "The Hobbit")
  2. author — Who wrote it (e.g., "J.R.R. Tolkien")
  3. lender — Who borrowed it? (None if no one has it)
  4. borrow_date — When was it borrowed? (None if available)
🗂️ Dictionary: The Perfect Container for a Book

A dictionary lets us store multiple pieces of information together using key-value pairs. Think of it like a label on each piece of data.

# One book represented as a dictionary book = { "title": "The Hobbit", # Key: "title", Value: "The Hobbit" "author": "J.R.R. Tolkien", # Key: "author", Value: "J.R.R. Tolkien" "lender": None, # Key: "lender", Value: None (not borrowed) "borrow_date": None # Key: "borrow_date", Value: None }

Why None? — In Python, None means "no value" or "empty". If a book isn't borrowed, there's no lender and no borrow date, so we use None.

📋 List of Dictionaries: The Complete Bookshelf

We have MANY books, so we put all the book dictionaries inside a list:

books = [ {"title": "The Hobbit", "author": "J.R.R. Tolkien", "lender": None, "borrow_date": None}, {"title": "1984", "author": "George Orwell", "lender": "Alice", "borrow_date": "2024-01-15"}, {"title": "The Python Handbook", "author": "Flavio Copes", "lender": None, "borrow_date": None} ] # books[0] → The first book (The Hobbit) # books[1] → The second book (1984) # books[2] → The third book (The Python Handbook) # books[1]["lender"] → "Alice" (who borrowed the second book)
⚠️ Important: Borrowed vs Available

How do we know if a book is borrowed?

  • If lender is None → Book is AVAILABLE
  • If lender has a name → Book is BORROWED

This is how we track the status of each book!

🔧 Part 1: The Librarian (backend_library.py)

This file is the "brain" of our library. It stores all the books and handles all the operations. Let's break down every single line!

1. Importing datetime (Line 2)

Line 2:

import datetime
What is import?

Python has lots of built-in tools we can use, but they're stored in "libraries" (also called "modules"). The import statement loads a library so we can use its tools.

datetime is Python's library for working with dates and times. We might use it later to automatically get today's date when someone borrows a book.

2. Creating the Data Storage (Lines 4-5)

Lines 4-5:

# Data storage
books = []
What is happening here?
  1. # Data storage — This is a comment. Comments start with # and are notes for humans. Python ignores them.
  2. books = [] — We create an empty list called books. This is where ALL our books will be stored.

Why empty? We start with nothing. The add_sample_data() function will fill it with example books, and users can add more later.

🔍 What is a "Global Variable"?

A global variable is a variable declared outside of any function. This means ALL functions in this file can access and modify it.

The books list is global — every function can see it and change it.

3. Adding Sample Data (Lines 7-14)

Lines 7-14:

def add_sample_data():
    """Adds sample data to the library."""
    global books
    books = [
        {"title": "The Hobbit", "author": "J.R.R. Tolkien", "lender": None, "borrow_date": None},
        {"title": "1984", "author": "George Orwell", "lender": "Alice", "borrow_date": "2024-01-15"},
        {"title": "The Python Handbook", "author": "Flavio Copes", "lender": None, "borrow_date": None}
    ]
Breaking it down line by line:
  1. def add_sample_data(): — We're defining a function called add_sample_data. The () means it takes no inputs (no parameters).
  2. """Adds sample data to the library.""" — This is a docstring. It's a special comment that describes what the function does. It's wrapped in triple quotes.
  3. global books — This tells Python: "I want to modify the global books variable, not create a new local one."
  4. books = [...] — We fill the books list with 3 sample books. Notice:
    • "The Hobbit" → Available (lender is None)
    • "1984" → Borrowed by Alice on 2024-01-15
    • "The Python Handbook" → Available
⚠️ Why global books?

In Python, if you want to change a global variable inside a function, you must use the global keyword. Without it, Python would create a new local variable with the same name, and the global one wouldn't change!

4. Adding a New Book (Lines 18-24)

Lines 18-24:

def add_book(title, author):
    new_book = {}
    new_book["title"] = title
    new_book["author"] = author
    new_book["lender"] = None
    new_book["borrow_date"] = None
    books.append(new_book)
What happens when we call add_book("Harry Potter", "J.K. Rowling")?
  1. new_book = {} — Create an empty dictionary. Think of it as an empty box for our new book's information.
  2. new_book["title"] = title — Put the title inside. If title is "Harry Potter", now we have {"title": "Harry Potter"}
  3. new_book["author"] = author — Add the author. Now: {"title": "Harry Potter", "author": "J.K. Rowling"}
  4. new_book["lender"] = None — New books aren't borrowed yet, so lender is None.
  5. new_book["borrow_date"] = None — Same for borrow_date.
  6. books.append(new_book) — Add this new book dictionary to the end of our books list. append() is a list method that adds items to the end.
✅ Final Result

After running add_book("Harry Potter", "J.K. Rowling"):

new_book = { "title": "Harry Potter", "author": "J.K. Rowling", "lender": None, "borrow_date": None } # This dictionary is now INSIDE the books list!

5. Listing All Books (Lines 27-28)

Lines 27-28:

def list_books():
    return books
What does this do?

This is the simplest function! It just returns the entire books list. When the frontend (library_app.py) needs to show all books, it calls this function.

6. Borrowing a Book (Lines 31-40)

Lines 31-40:

def borrow_book(title, lender, date):
    for book in books:
        # 1st Run -> book = {"title": "The Hobbit", ...}
        # 2nd Run -> book = {"title": "1984", ...}
        # 3rd Run -> book = {"title": "The Python Handbook", ...}
        if book["title"] == title:
            book["lender"] = lender
            book["borrow_date"] = date

    return books
Let's trace through: borrow_book("The Hobbit", "Bob", "2024-02-01")
  1. for book in books: — Start a loop. Each time through, book becomes one dictionary from the books list.
  2. First loop iteration: book = The Hobbit dictionary
    • if book["title"] == title → "The Hobbit" == "The Hobbit" → TRUE!
    • book["lender"] = lender → Set lender to "Bob"
    • book["borrow_date"] = date → Set date to "2024-02-01"
  3. Second and Third iterations: The titles don't match, so nothing happens.
  4. return books — Return the updated list.
✅ After Borrowing

The Hobbit dictionary changed from:

BEFORE: {"title": "The Hobbit", "author": "J.R.R. Tolkien", "lender": None, "borrow_date": None} AFTER: {"title": "The Hobbit", "author": "J.R.R. Tolkien", "lender": "Bob", "borrow_date": "2024-02-01"}

7. Returning a Book (Lines 43-52)

Lines 43-52:

def return_book(title): # title -> 1984
    for book in books:
        if book["title"] == title:
            book["lender"] = None
            book["borrow_date"] = None
    
    return books
How returning works:

Returning is the opposite of borrowing. We find the book by title, then set lender and borrow_date back to None.

If someone calls return_book("1984"):

  1. Loop through books until we find "1984"
  2. Set book["lender"] = None (was "Alice")
  3. Set book["borrow_date"] = None (was "2024-01-15")
  4. The book is now available again!

8. Getting All Borrowed Books (Lines 55-60)

Lines 55-60:

def get_borrowed_books():
    borrow_names = [] # [{...}, {...}]
    for book in books:
        if book["lender"] != None:
            borrow_names.append(book)
    return borrow_names
This function filters the list to show only borrowed books:
  1. borrow_names = [] — Create an empty list to store borrowed books.
  2. for book in books: — Loop through every book.
  3. if book["lender"] != None: — If the lender is NOT None (meaning someone borrowed it)...
  4. borrow_names.append(book) — Add this book to our results.
  5. return borrow_names — Return only the borrowed books.
🔍 != vs ==
  • == means "is equal to"
  • != means "is NOT equal to"

So book["lender"] != None checks if there IS a lender (book is borrowed).

🖥️ Part 2: The Front Desk (library_app.py)

This file is what the user sees and interacts with. It displays menus, collects input, and communicates with the backend.

1. Connecting to the Backend (Line 2)

Line 2:

import backend_library
What does this do?

This loads the backend_library.py file. Now we can use ALL the functions defined in that file by writing backend_library.function_name().

For example: backend_library.add_book("Title", "Author")

⚠️ Important: Both Files Must Be in the Same Folder!

For import backend_library to work, backend_library.py must be in the same folder as library_app.py.

2. The main() Function & Sample Data (Lines 4-6)

Lines 4-6:

def main():
    # Initialize with sample data
    backend_library.add_sample_data()
Starting the program:
  1. def main(): — Define the main function. This is where the program's logic lives.
  2. backend_library.add_sample_data() — Call the backend function to load sample books. This way, when the program starts, there are already some books to work with.

3. The Infinite Menu Loop (Lines 8-16)

Lines 8-16:

while True:
    print("\n--- Library App ---")
    print("1. Add Book")
    print("2. List All Books")
    print("3. Borrow Book")
    print("4. Return Book")
    print("5. View Borrowed Books")
    print("6. Exit")
    
    choice = input("Enter your choice: ")
How the menu works:
  1. while True: — Creates an infinite loop. The program will keep running until we explicitly break out of it.
  2. print("\n--- Library App ---") — Print the header. The \n adds a blank line before it for readability.
  3. print("1. Add Book") etc. — Show all the options the user can choose from.
  4. choice = input("Enter your choice: ") — Wait for the user to type something and press Enter. Store their answer in choice.

4. Adding a Book (Lines 19-23)

Lines 19-23:

if choice == '1':
    title = input("Enter book title: ")
    author = input("Enter author: ")
    backend_library.add_book(title, author)
    print("Book added successfully.")
Step by step:
  1. if choice == '1': — If the user typed "1"...
  2. title = input("Enter book title: ") — Ask for the book's title
  3. author = input("Enter author: ") — Ask for the author
  4. backend_library.add_book(title, author) — Send this info to the backend!
  5. print("Book added successfully.") — Confirm to the user
🔗 The Frontend-Backend Connection

Notice this pattern:

  1. Frontend collects data from user (input())
  2. Frontend sends data to backend (backend_library.add_book(...))
  3. Backend does the work (creates dictionary, adds to list)
  4. Frontend confirms to user (print())

The frontend NEVER touches the books list directly!

5. Listing All Books (Lines 25-32)

Lines 25-32:

elif choice == '2':
    books = backend_library.list_books()
    if not books:
        print("No books in library.")
    else:
        for book in books:
            status = f"Borrowed by {book['lender']} on {book['borrow_date']}" if book['lender'] else "Available"
            print(f"- {book['title']} by {book['author']} ({status})")
This is the most complex display logic. Let's break it apart:
  1. books = backend_library.list_books() — Get the list of all books from the backend.
  2. if not books: — If the list is empty...
  3. print("No books in library.") — Tell the user there are no books.
  4. else: — Otherwise (there ARE books)...
  5. for book in books: — Loop through each book dictionary.
  6. status = f"Borrowed by..." if book['lender'] else "Available" — This is a ternary expression. It means:
    • IF book['lender'] has a value → status = "Borrowed by [name] on [date]"
    • ELSE → status = "Available"
  7. print(f"- {book['title']} by {book['author']} ({status})") — Display the book info.
✅ Example Output
- The Hobbit by J.R.R. Tolkien (Available) - 1984 by George Orwell (Borrowed by Alice on 2024-01-15) - The Python Handbook by Flavio Copes (Available)

Lines 34-43:

elif choice == '3':

  3. backend_library.borrow_book(title, lender, date) — Call the backend to update the book's information.
  4. The if/else shows a success or failure message.

10. The Entry Point (Lines 66-67)

Lines 66-67:

What is this magic?

This is Python's way of saying: "If this file is being run directly (not imported), execute the main() function."

Without this, the code inside main() would never run! This line is the entry point — where the program starts.

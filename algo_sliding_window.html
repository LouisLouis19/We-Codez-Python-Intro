What is the Sliding Window Technique?

The Sliding Window technique is used when you need to look at a group of consecutive elements in a list — also called a subarray — and find the best (maximum, minimum, etc.) one.

Instead of recalculating everything from scratch for each subarray, we "slide" the window one step at a time: we add the new element that enters the window and remove the old element that leaves it.

Real-Life Analogy: A Moving Picture Frame

Imagine you have a very long painting on a wall, and you have a small picture frame that can only show 3 sections at a time. You slide the frame from left to right, looking at what's in the frame at each position.

Each time you slide the frame one step:

  • The new rightmost section enters the frame.
  • The old leftmost section exits the frame.
  • Everything else in between stays. You don't need to re-examine it!

The Key Problem Type

A classic example: "Find the maximum sum of any 3 consecutive numbers in a list." 

nums = [2, 1, 5, 1, 3, 2]
k = 3   # Window size

# Possible windows of size 3:
# [2, 1, 5]  → sum = 8
# [1, 5, 1]  → sum = 7
# [5, 1, 3]  → sum = 9  ← MAX!
# [1, 3, 2]  → sum = 6

# Answer: 9

Brute Force vs. Sliding Window

Brute Force (Slow)

Calculate the sum of every possible window from scratch. 

def max_sum_brute(nums, k):
    max_sum = 0

    for i in range(len(nums) - k + 1):
        window_sum = 0
        for j in range(i, i + k):     # Sum up k elements starting at i
            window_sum += nums[j]
        max_sum = max(max_sum, window_sum)

    return max_sum

# Problem: For a list of 1000 items, window size k=100
# → checks 100 numbers for each of 900 starting positions = 90,000 operations!

Sliding Window (Fast)

Calculate the first window sum, then slide: add the new element, subtract the old element. 

# nums = [2, 1, 5, 1, 3, 2],  k = 3
#
# Initial window: [2, 1, 5]  → sum = 8
#
# Slide right by 1:
#   Add nums[3]=1 (entering window)
#   Subtract nums[0]=2 (leaving window)
#   New sum = 8 + 1 - 2 = 7
#   Window: [1, 5, 1]
#
# Slide right by 1:
#   Add nums[4]=3 (entering)
#   Subtract nums[1]=1 (leaving)
#   New sum = 7 + 3 - 1 = 9   ← MAX!
#   Window: [5, 1, 3]
#
# Slide right by 1:
#   Add nums[5]=2 (entering)
#   Subtract nums[2]=5 (leaving)
#   New sum = 9 + 2 - 5 = 6
#   Window: [1, 3, 2]

The sliding window approach is much more efficient — we do each addition and subtraction only once per element.

Maximum Sum Subarray — Step by Step

def max_sum_subarray(nums, k):
    """
    Find the maximum sum of any contiguous subarray of size k.
    """
    if k > len(nums) or k <= 0:
        return 0

    # Step 1: Calculate the sum of the first window
    window_sum = sum(nums[:k])    # Sum of first k elements
    max_sum = window_sum

    # Step 2: Slide the window from index k to the end
    for i in range(k, len(nums)):
        window_sum += nums[i]        # Add the new element entering the window
        window_sum -= nums[i - k]    # Subtract the element leaving the window

        max_sum = max(max_sum, window_sum)   # Update max if needed

    return max_sum


# --- Test it! ---
nums1 = [2, 1, 5, 1, 3, 2]
print(max_sum_subarray(nums1, 3))   # Output: 9  (subarray: [5, 1, 3])

nums2 = [1, 4, 2, 9, 7, 3, 8]
print(max_sum_subarray(nums2, 4))   # Output: 22 (subarray: [9, 7, 3, 8] = nope)
# Let's check: [1,4,2,9]=16, [4,2,9,7]=22, [2,9,7,3]=21, [9,7,3,8]=27
print(max_sum_subarray(nums2, 4))   # Output: 27 (subarray: [9, 7, 3, 8])

Full Walkthrough Trace

Let's trace through nums = [2, 1, 5, 1, 3, 2], k = 3 in detail:

nums   =  [2,  1,  5,  1,  3,  2]
index  =   0   1   2   3   4   5

Step 1: Build the first window [index 0..2]
window_sum = 2 + 1 + 5 = 8
max_sum = 8

Step 2: i=3 (slide window right)
  Add  nums[3] = 1  (enters window)
  Remove nums[3-3] = nums[0] = 2  (leaves window)
  window_sum = 8 + 1 - 2 = 7
  Window is now [1, 5, 1]
  max_sum = max(8, 7) = 8

Step 3: i=4 (slide again)
  Add  nums[4] = 3  (enters)
  Remove nums[4-3] = nums[1] = 1  (leaves)
  window_sum = 7 + 3 - 1 = 9
  Window is now [5, 1, 3]
  max_sum = max(8, 9) = 9  ← new max!

Step 4: i=5 (final slide)
  Add  nums[5] = 2  (enters)
  Remove nums[5-3] = nums[2] = 5  (leaves)
  window_sum = 9 + 2 - 5 = 6
  Window is now [1, 3, 2]
  max_sum = max(9, 6) = 9

Final Answer: 9

Variations

Variation 1: Minimum Sum Subarray

Same idea — but we track the smallest window sum. Works even with negative numbers. 

def min_sum_subarray(nums, k):
    if k > len(nums) or k <= 0:
        return 0

    window_sum = sum(nums[:k])
    min_sum = window_sum

    for i in range(k, len(nums)):
        window_sum += nums[i]
        window_sum -= nums[i - k]
        min_sum = min(min_sum, window_sum)   # Use min instead of max!

    return min_sum

nums = [3, -1, 4, -2, -6, 5]
print(min_sum_subarray(nums, 2))   # Output: -8  (subarray: [-2, -6])

Variation 2: Maximum K-Digit Number

Find the maximum number that can be formed by joining any k consecutive digits from the list. 

# nums = [2, 3, 9, 7],  k = 2
# Windows of size 2:
# [2, 3] → join → "23" → 23
# [3, 9] → join → "39" → 39
# [9, 7] → join → "97" → 97  ← MAX!

def find_max_k_digit_number(nums, k):
    if k > len(nums) or k <= 0:
        return 0

    max_num = 0

    for i in range(len(nums) - k + 1):
        window = nums[i : i + k]           # Get the window slice
        joined = int("".join(map(str, window)))   # Join digits to form a number
        max_num = max(max_num, joined)

    return max_num

nums = [2, 3, 9, 7]
print(find_max_k_digit_number(nums, 2))  # Output: 97

When Should I Use Sliding Window?

Look for these clues in a problem:

  • The problem mentions "subarray of size k" or "consecutive elements".
  • You need to find a maximum, minimum, or sum across all windows.
  • The window size is fixed (always the same size — this is the simplest case).
  • You want to avoid recalculating the entire window each time (avoid brute force).

The key insight: what you remove from one side of the window is exactly what you add to the other. This means you only do O(1) work per element instead of O(k).

1. Find Maximum Sum

Solution 
# Window 1: [1, 4, 2, 9] = 16
# Window 2: [4, 2, 9, 7] = 22
# Window 3: [2, 9, 7, 3] = 21
# Window 4: [9, 7, 3, 8] = 27  ← MAX

nums = [1, 4, 2, 9, 7, 3, 8]
print(max_sum_subarray(nums, 4))   # Output: 27

2. Find Minimum Sum

Find the minimum sum of any 3 consecutive numbers in [5, -2, 4, -1, -6, 8, 1].

Solution 
# Windows: [5,-2,4]=7, [-2,4,-1]=1, [4,-1,-6]=-3, [-1,-6,8]=1, [-6,8,1]=3
# Minimum = -3

nums = [5, -2, 4, -1, -6, 8, 1]
print(min_sum_subarray(nums, 3))   # Output: -3

3. The "Slide" Explained

In your own words, explain why we do window_sum += nums[i] and window_sum -= nums[i - k] when sliding the window. What do these two lines represent?

Solution 
# window_sum += nums[i]      → The new element on the RIGHT enters the window.
#                               We add it because it's now part of the group.

# window_sum -= nums[i - k]  → The old element on the LEFT exits the window.
#                               We subtract it because it's no longer in the group.

# Example: window=[1, 5, 1], sliding right
# New element: 3 enters → add 3
# Old element: 1 leaves → subtract 1
# New window: [5, 1, 3], new sum = old_sum + 3 - 1

4. K-Digit Number Challenge

What is the maximum 3-digit number that can be formed from consecutive digits in [4, 1, 7, 3, 9, 2]?

Solution 
# Windows of size 3:
# [4,1,7] → 417
# [1,7,3] → 173
# [7,3,9] → 739
# [3,9,2] → 392
# Maximum: 739

nums = [4, 1, 7, 3, 9, 2]
print(find_max_k_digit_number(nums, 3))  # Output: 739

5. Think About It

If k = 1, what does the sliding window return for max_sum_subarray([3, 7, 1, 9, 2], 1)? Does this make sense?

Solution 
# k=1 means the "window" is just a single element.
# The max sum of a window of size 1 is just the max element in the list.

# [3]=3, [7]=7, [1]=1, [9]=9, [2]=2 → Maximum = 9

print(max_sum_subarray([3, 7, 1, 9, 2], 1))   # Output: 9
# This is the same as: max([3, 7, 1, 9, 2]) = 9 ✓

Time Complexity

The whole point of the Sliding Window technique is to eliminate the slow inner loop of the brute force approach. Here is how they compare:

Approach Time Complexity Explanation
Brute Force (recalculate each window) O(n × k) For each of the ~n windows, we sum up k elements from scratch.
Sliding Window O(n) We build the first window once, then update it with one add and one subtract per step.

What does O(n × k) vs O(n) mean in practice?

# n = total number of items in the list
# k = window size

# BRUTE FORCE — O(n × k):
# n=1000, k=100 → 1000 × 100 = 100,000 operations
# n=1000, k=500 → 1000 × 500 = 500,000 operations  ← Gets worse as k grows!

# SLIDING WINDOW — O(n):
# n=1000, k=100 → 1000 operations (regardless of k!)
# n=1000, k=500 → 1000 operations  ← k doesn't matter!

Why is it O(n)?

Each element in the list is added to the window exactly once and removed from the window exactly once. So every element is processed at most twice — giving us a total of 2n operations, which simplifies to O(n).

Space Complexity

The fixed-size sliding window only keeps track of the current window sum and the maximum — no extra lists or data structures needed. That's O(1) extra space.

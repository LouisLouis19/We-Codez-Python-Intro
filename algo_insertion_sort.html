What is Insertion Sort?

Insertion Sort is a simple and intuitive sorting algorithm that builds the sorted list one element at a time.

At each step, we pick the next element from the "unsorted" portion and find the correct spot for it within the already-sorted portion by shifting larger elements to the right.

Real-Life Analogy: Sorting a Hand of Cards

Think about how you sort a hand of playing cards:

  • You start with one card in your left hand — it's already sorted (trivially).
  • You pick up the next card from the table.
  • You compare it with the cards already in your hand, moving from right to left.
  • You slide cards right to make room and insert the new card in the correct spot.
  • Repeat for every card until all are in your hand, in order.

Two Zones: Sorted and Unsorted

At any point during Insertion Sort, the list is divided into two portions:

Zone What it contains How it changes
Sorted (left portion) Elements already in sorted order Grows by 1 each step
Unsorted (right portion) Elements not yet processed Shrinks by 1 each step 
numbers = [5, 2, 8, 1, 9]

# Start:     [5] | [2, 8, 1, 9]    → sorted: [5], pick next: 2
# After 1:   [2, 5] | [8, 1, 9]    → sorted: [2,5], pick next: 8
# After 2:   [2, 5, 8] | [1, 9]    → sorted: [2,5,8], pick next: 1
# After 3:   [1, 2, 5, 8] | [9]    → sorted: [1,2,5,8], pick next: 9
# After 4:   [1, 2, 5, 8, 9]       → ALL SORTED ✓

How Insertion Sort Works — Step by Step

Let's trace through [5, 2, 8, 1, 9] in full detail.

Step 1: Start at index 1 (the second element)

# The first element [5] is trivially "sorted" (a single element is always sorted).
# Pick the key = arr[1] = 2

key = 2
# Now find where to insert 2 in the sorted portion [5]:
# Compare 2 with 5: 2 < 5 → shift 5 to the right
# Insert 2 at index 0
After Step 1: [2, 5, 8, 1, 9]

Step 2: index 2, key = 8

key = 8
# Sorted portion: [2, 5]
# Compare 8 with 5: 8 >= 5 → STOP. Insert 8 at its current position (index 2)
After Step 2: [2, 5, 8, 1, 9]  (no change needed)

Step 3: index 3, key = 1

key = 1
# Sorted portion: [2, 5, 8]
# Compare 1 with 8: 1 < 8 → shift 8 right → [2, 5, _, 8, 9]
# Compare 1 with 5: 1 < 5 → shift 5 right → [2, _, 5, 8, 9]
# Compare 1 with 2: 1 < 2 → shift 2 right → [_, 2, 5, 8, 9]
# No more to compare → Insert 1 at index 0
After Step 3: [1, 2, 5, 8, 9]

Step 4: index 4, key = 9

key = 9
# Sorted portion: [1, 2, 5, 8]
# Compare 9 with 8: 9 >= 8 → STOP. Insert 9 at its current position (index 4)
After Step 4: [1, 2, 5, 8, 9]

Final sorted list: [1, 2, 5, 8, 9] ✓

Insertion Sort in Python

def insertion_sort(arr):
    n = len(arr)

    # Start from the second element (index 1)
    # The first element [arr[0]] is already "sorted" by itself
    for i in range(1, n):
        key = arr[i]    # The element we want to insert into the sorted portion
        j = i - 1      # Start comparing from the element just left of key

        # Shift elements of the sorted portion that are GREATER than key, one position to the right
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]    # Shift this element right by one
            j -= 1                 # Move left to compare the next element

        # Place the key in its correct position
        arr[j + 1] = key

    return arr


# --- Test it! ---
numbers = [5, 2, 8, 1, 9]
print(insertion_sort(numbers))    # Output: [1, 2, 5, 8, 9]

more = [10, 2, 78, 4, 45, 32]
print(insertion_sort(more))       # Output: [2, 4, 10, 32, 45, 78]

Understanding the Code

  • key = arr[i]: This is the element we're currently trying to insert. We save it because we're about to overwrite the position.
  • j = i - 1: We start looking to the left of the current element.
  • while j >= 0 and arr[j] > key: While we haven't gone too far left AND the current element is bigger than our key — keep shifting right.
  • arr[j + 1] = arr[j]: Shift the bigger element one position to the right.
  • arr[j + 1] = key: Place the key in the gap we just made.

Visualizing the Shift and Insert

The trickiest part to understand is the "shift and insert" process. Let's visualize it: 

# Inserting key=1 into sorted portion [2, 5, 8]:
# Initial: [2, 5, 8, (1), 9]
#                      ^key

# Step a: Compare 8 and 1: 8 > 1 → shift 8 right
# [2, 5, (8), 8, 9]   ← "hole" opens at index 2

# Step b: Compare 5 and 1: 5 > 1 → shift 5 right
# [2, (5), 5, 8, 9]   ← "hole" opens at index 1

# Step c: Compare 2 and 1: 2 > 1 → shift 2 right
# [(2), 2, 5, 8, 9]   ← "hole" opens at index 0

# Step d: j = -1 → stop. Insert key=1 at j+1=0
# [1, 2, 5, 8, 9]   ✓

The key we saved at the start is placed into the "hole" created by the chain of right-shifts.

Insertion Sort on Strings

Just like Bubble Sort, Insertion Sort works on strings using Python's alphabetical comparison. 

def insertion_sort_strings(arr):
    n = len(arr)

    for i in range(1, n):
        key = arr[i]
        j = i - 1

        # Shift strings that come AFTER key alphabetically
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1

        arr[j + 1] = key

    return arr


fruits = ["Cherry", "Date", "Apple", "Elderberry", "Banana"]
print(insertion_sort_strings(fruits))
# Output: ['Apple', 'Banana', 'Cherry', 'Date', 'Elderberry']
# Trace for "Cherry", "Date", "Apple":
# i=1, key="Date": Compare with "Cherry" → "Cherry" < "Date" → no shift. Insert "Date" at pos 1.
# Sorted: ["Cherry", "Date"]
#
# i=2, key="Apple": Compare with "Date" → "Date" > "Apple" → shift "Date" right.
#   Compare with "Cherry" → "Cherry" > "Apple" → shift "Cherry" right.
#   j = -1 → insert "Apple" at pos 0.
# Sorted: ["Apple", "Cherry", "Date"]

Bubble Sort vs. Insertion Sort

Feature Bubble Sort Insertion Sort
Basic idea Compare adjacent pairs, swap if wrong order Pick next element, insert into correct position
Number of swaps Many swaps (each pass can swap many pairs) Fewer shifts (only shifts as far as needed)
Performance on nearly sorted data With optimization: fast Naturally fast (inner loop barely runs)
Worst-case complexity O(n²) O(n²)
Best-case complexity O(n) with early-stop optimization O(n) — inner loop doesn't run if already sorted

In practice, Insertion Sort is generally considered better than Bubble Sort because it makes fewer comparisons and swaps on average.

Practice Questions

1. Trace Insertion Sort

Trace Insertion Sort on [8, 3, 7, 1, 5]. Show the state of the list after inserting each element.

Solution 
Initial:  [8, 3, 7, 1, 5]

i=1, key=3: 8>3 → shift 8 right → Insert 3 at index 0
→ [3, 8, 7, 1, 5]

i=2, key=7: 8>7 → shift 8 right → 3>7? NO → Insert 7 at index 1
→ [3, 7, 8, 1, 5]

i=3, key=1: 8>1 → shift; 7>1 → shift; 3>1 → shift; j=-1 → Insert 1 at index 0
→ [1, 3, 7, 8, 5]

i=4, key=5: 8>5 → shift; 7>5 → shift; 3>5? NO → Insert 5 at index 2
→ [1, 3, 5, 7, 8]

Final: [1, 3, 5, 7, 8] ✓

2. Best Case

What happens when you run Insertion Sort on [1, 2, 3, 4, 5]? How many times does the inner while loop actually run?

Solution 
# For each i from 1 to 4:
#   key = arr[i]
#   Compare with arr[i-1]: is arr[i-1] > key?
#   Since the list is already sorted, arr[i-1] <= arr[i] ALWAYS.
#   So the while loop runs ZERO times for every element!
#
# The inner loop never runs → only O(n) total work → very fast!

print(insertion_sort([1, 2, 3, 4, 5]))   # Output: [1, 2, 3, 4, 5]

3. Worst Case

What is the worst case input for Insertion Sort? How many shifts does it make?

Solution 
# Worst case: a list sorted in REVERSE order, e.g., [5, 4, 3, 2, 1]
# 
# i=1, key=4: shift 5 (1 shift)
# i=2, key=3: shift 5, shift 4 (2 shifts)
# i=3, key=2: shift 5, 4, 3 (3 shifts)
# i=4, key=1: shift 5, 4, 3, 2 (4 shifts)
# Total shifts = 1+2+3+4 = 10 = n(n-1)/2 → O(n²)

print(insertion_sort([5, 4, 3, 2, 1]))   # Output: [1, 2, 3, 4, 5]

5. Bubble vs. Insertion

For the list [2, 1, 3, 4, 5], which algorithm performs fewer operations — Bubble Sort (with early stopping) or Insertion Sort? Explain why.

Solution 
# This list is NEARLY sorted — only positions 0 and 1 are swapped.
#
# BUBBLE SORT (with early stopping):
#   Pass 1: Compare [2,1]→swap→[1,2,3,4,5], then compare [2,3],[3,4],[4,5] → no swaps after first
#   swapped=True, so continue
#   Pass 2: [1,2,3,4,5] → no swaps → swapped=False → STOP
#   Total: 2 passes
#
# INSERTION SORT:
#   i=1, key=1: 2>1 → shift → Insert 1 at index 0 → [1,2,3,4,5]
#   i=2, key=3: 2>3? NO → no shift
#   i=3, key=4: 3>4? NO → no shift
#   i=4, key=5: 4>5? NO → no shift
#   Total: 4 passes through outer loop, but only 1 shift total
#
# Insertion Sort does fewer TOTAL SWAPS/SHIFTS for nearly-sorted data.
# Both are fast, but Insertion Sort is generally more efficient on nearly-sorted lists.

Time Complexity

Insertion Sort's performance depends heavily on the input. It has a particularly nice best case — making it a great choice for lists that are already nearly sorted.

Case Time Complexity When does it happen?
Best Case O(n) The list is already sorted — the inner while loop never runs. One pass is enough.
Average Case O(n²) Elements are in random order — on average, each element shifts about halfway back.
Worst Case O(n²) The list is sorted in reverse — every new element must shift all the way to the front.

What does O(n²) mean in practice?

# n = number of items in the list

# WORST CASE — reverse sorted list like [5, 4, 3, 2, 1]:
# Element at index 1 shifts 1 time
# Element at index 2 shifts 2 times
# Element at index 3 shifts 3 times
# ...
# Total shifts = 1 + 2 + 3 + ... + (n-1) = n(n-1)/2  →  O(n²)

# BEST CASE — already sorted list like [1, 2, 3, 4, 5]:
# Inner while loop runs 0 times for every element
# Only the outer loop runs → O(n)  ← Much faster!

Insertion Sort vs. Bubble Sort — Same Complexity, Different Feel

Both have O(n²) worst case, but Insertion Sort tends to be faster in practice because:

  • It stops shifting as soon as it finds the right position — no unnecessary comparisons.
  • It is naturally adaptive: the more sorted the input already is, the faster it runs.
  • It makes fewer total swaps than Bubble Sort on average.

Space Complexity

Insertion Sort is in-place — it only needs the key variable to temporarily hold the element being inserted, and uses no extra lists or data structures. That's O(1) extra space.

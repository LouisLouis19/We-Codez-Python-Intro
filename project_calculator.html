🎯 What Are We Building?

We're building a Simple Calculator that can add, subtract, multiply, and divide numbers. The user picks an operation, enters two numbers, and gets the result!

🍽️ Analogy: The Restaurant

Think of this program like a restaurant:

  • The Frontend (calculator.py) is the Waiter. It talks to the customer (you), takes your order (numbers and operation), and brings you the food (result). It doesn't cook the food itself.
  • The Backend (backend_math.py) is the Chef. It stays in the kitchen, receives orders from the waiter, performs the actual cooking (math), and hands the dish back. It never talks to the customer directly.
🧠 Why Two Files?

Separating code into Frontend and Backend is a fundamental programming practice called Separation of Concerns:

File Role Handles Uses print/input?
calculator.py Frontend (UI) User interaction (menus, input, display) ✅ YES
backend_math.py Backend (Logic) Actual calculations ❌ NO

Benefits: If you want to change how the menu looks, you only touch the frontend. If you want to add a new math operation, you only touch the backend!

🔧 Part 1: The Chef (backend_math.py)

This file handles ALL the math. It's pure logic. It doesn't know about input() or print() because the Chef doesn't talk to customers.

1. The Add Function (Lines 1-4)

Lines 1-4:

def add(x, y): 
    """Returns the sum of x and y."""
    total = x + y
    return total
Let's break down every part:
  1. def add(x, y): — This creates a new function called add.
    • def = "define" (I'm creating a new function)
    • add = the name of the function
    • (x, y) = parameters — the inputs this function needs
    • : = marks the start of the function body
  2. """Returns the sum of x and y.""" — This is a docstring. It's a special comment (inside triple quotes) that describes what the function does. It's documentation for other programmers (and your future self!).
  3. total = x + y — Creates a variable called total and stores the result of x + y in it.
  4. return total — This is crucial! The function gives the answer back to whoever called it. Without return, the calculation would be lost!
🔄 Return vs Print — What's the Difference?

print() displays something on the screen for humans to see. The computer forgets the value immediately after.

return gives a value BACK to the code that called the function. The value can be stored, used in more calculations, or displayed later.

# Example with return: result = add(5, 3) # result now contains 8 print(result) # Shows: 8 print(result * 2) # Shows: 16 (we can still use it!) # If add() used print instead of return: result = add(5, 3) # Would print "8" but result would be None! print(result * 2) # ERROR! None * 2 doesn't work

2. The Subtract Function (Lines 6-9)

Lines 6-9:

def subtract(x, y):
    """Returns the difference of x and y."""
    total = x - y
    return total
How it works:

Same structure as add, but uses - instead of +!

If we call subtract(10, 3):

  1. x becomes 10
  2. y becomes 3
  3. total = 10 - 3 = 7
  4. return 7 — gives back 7

Lines 11-14:

def multiply(x, y):
    """Returns the product of x and y."""
    total = x * y
    return total
Multiplication in Python:

In Python, we use * for multiplication (not ×).

multiply(4, 5) would return 20.

4. The Divide Function — Handling Errors! (Lines 16-21)

Lines 16-21:

def divide(x, y):
    """Returns the quotient of x and y. Raises ValueError on division by zero."""
    if y == 0:
        raise ValueError("Division by Zero Error") 
    total = x / y
    return total
Why is divide different?

In math, you cannot divide by zero. If we try 5 / 0, Python would crash with an error!

  1. if y == 0: — Check: is the second number (divisor) zero?
  2. raise ValueError("Division by Zero Error") — If yes, we "raise" an error ourselves. This is like the Chef saying: "I refuse to cook this! It's impossible!"
  3. If y is NOT zero, we continue normally and return x / y.
⚠️ What is raise?

raise creates an error on purpose. It's our way of saying "Something is wrong! I can't continue!"

This error will "bubble up" to whoever called the function. The frontend will need to "catch" this error (using try/except) and handle it gracefully.

🖥️ Part 2: The Waiter (calculator.py)

This file handles the User Interface — everything the user sees and interacts with.

1. Importing the Backend (Lines 1-2)

Lines 1-2:

import backend_math
import sys
What is import?
  1. import backend_math — This links our frontend to the backend file. Now we can use ALL the functions from backend_math.py by writing backend_math.function_name().
  2. import sys — Imports Python's system module. This is optional and can be used for advanced features (like exiting the program).
📦 Think of Imports Like Tools in a Toolbox

backend_math is the toolbox. add, subtract, multiply, divide are the tools inside.

To use a tool: backend_math.add(5, 3) = "Open the toolbox, use the add tool"

2. The Input Validator (Lines 4-10)

Lines 4-10:

def get_number(prompt):
    """Helper to get a valid number from user input."""
    while True:
        try:
            return float(input(prompt))
        except ValueError:
            print("Invalid input. Please enter a numeric value.")
Why do we need this?

The Problem: If we ask for a number and the user types "banana", the program crashes!

The Solution: This function keeps asking until the user gives a valid number.

  1. def get_number(prompt): — Takes a "prompt" (the message to display).
  2. while True: — Creates an infinite loop. Keep trying forever until we succeed!
  3. try: — "Try to do this dangerous thing..."
  4. return float(input(prompt)) — Ask for input, convert it to a number (float), and return it. If this works, we exit the loop!
  5. except ValueError: — "...if it fails with a ValueError, do this instead:"
  6. print("Invalid input...") — Tell the user what went wrong. Then the loop restarts and asks again!
✅ This Prevents Crashes!
# Without get_number(): >>> Enter number: banana ERROR! Program crashes. # With get_number(): >>> Enter number: banana Invalid input. Please enter a numeric value. >>> Enter number: 42 (Works! Continues happily.)

"-" * 40 — The * with strings means "repeat".

This prints: ---------------------------------------- (40 dashes)

We use it to visually separate sections and make the output look cleaner.

  1. def main(): — Define the main function where everything happens.

5. The Infinite Menu Loop (Lines 19-27)

Lines 19-27:

while True: # Calculator never stops 
    print("\nPlease select an operation:")
    print("1. Add (+)")
    print("2. Subtract (-)")
    print("3. Multiply (*)")
    print("4. Divide (/)")
    print("5. Exit")
    
    choice = input("\nEnter your choice (1/2/3/4/5): ").strip()
How the menu works:
  1. while True: — Keep showing the menu forever. This is the calculator's main loop.
  2. print("\n...") — The \n adds a blank line before the text.
  3. print("1. Add (+)") etc. — Display all options.
  4. choice = input(...).strip() — Get the user's choice. The .strip() removes any accidental spaces before/after their input.

6. Handling the Exit Option (Lines 29-31)

Lines 29-31:

if choice == '5': # Calculator only stops on Exit
    print("\nThank you for using the calculator. Goodbye!")
    break
Breaking out of the loop:

break immediately exits the while True loop. This is the ONLY way the program ends normally.

7. Getting Numbers and Calling the Backend (Lines 33-52)

Lines 33-52:

if choice in ('1', '2', '3', '4'):
    try:
        num1 = get_number("Enter the first number: ") 
        num2 = get_number("Enter the second number: ")
        
        result = None
        operation = ""

        if choice == '1':
            result = backend_math.add(num1, num2)
            operation = "+"
        elif choice == '2':
            result = backend_math.subtract(num1, num2)
            operation = "-"
        elif choice == '3':
            result = backend_math.multiply(num1, num2)
            operation = "*"
        elif choice == '4':
            result = backend_math.divide(num1, num2)
            operation = "/"
Breaking it down:
  1. if choice in ('1', '2', '3', '4'): — Check if the choice is one of the valid options. This is cleaner than writing if choice == '1' or choice == '2' or ...
  2. try: — Start a "try block" in case something goes wrong (like division by zero).
  3. num1 = get_number(...) — Use our helper to safely get the first number.
  4. num2 = get_number(...) — Same for the second number.
  5. result = None — Create a variable to store the answer (starts empty).
  6. operation = "" — Create a variable to store the symbol (for display).
  7. if choice == '1': — If user chose "1" (Add)...
    • result = backend_math.add(num1, num2) — Call the backend!
    • operation = "+" — Remember the symbol for display.
  8. Same pattern for subtract, multiply, and divide.
🔗 The Frontend-Backend Connection

This is where the Waiter talks to the Chef:

# User selects "1" (Add), then enters 5 and 3 result = backend_math.add(num1, num2) # ^^^^^^^^^^^^^^^--- the backend file # ^^^--- the function from that file # ^^^^^^^^^ --- the numbers from user # The add() function runs and returns 8 # result now contains 8

8. Displaying the Result (Lines 54-56)

Lines 54-56:

print_separator()
print(f"Result: {num1} {operation} {num2} = {result}")
print_separator()
F-strings for formatting:

f"..." is an f-string (formatted string). The curly braces {} get replaced with the values of the variables inside them.

# If num1=5, operation="+", num2=3, result=8: print(f"Result: {num1} {operation} {num2} = {result}") # Output: Result: 5 + 3 = 8

9. Catching Errors from the Backend (Lines 58-61)

Lines 58-61:

except ValueError as e:
    print(f"Error: {e}")
except Exception as e:
    print(f"An unexpected error occurred: {e}")
The safety net:

Remember when the divide function raises an error for division by zero? This is where we catch that error!

  1. except ValueError as e: — If a ValueError occurred, catch it and store the error message in e.
  2. print(f"Error: {e}") — Display the error message nicely.
  3. except Exception as e: — Catch ANY other error (just in case!).
✅ Graceful Error Handling
# User tries 5 / 0: Enter the first number: 5 Enter the second number: 0 Error: Division by Zero Error # Instead of CRASHING, we show a nice message and continue!

10. Handling Invalid Menu Choices (Lines 62-63)

Lines 62-63:

else:
    print("Invalid choice. Please select a valid option from the menu.")
Catching bad input:

If the user types something other than 1, 2, 3, 4, or 5 (like "7" or "hello"), we politely ask them to try again.

11. The Entry Point (Lines 65-66)

Lines 65-66:

if __name__ == "__main__":
    main()
What is this?

This is Python's way of saying: "If this file is being run directly (not imported), execute the main() function."

Without this line, the main() function would never be called and nothing would happen when you run the file!

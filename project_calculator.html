The Big Picture: Frontend vs Backend

Analogy: The Restaurant

Think of this program like a restaurant:

  • The Frontend (calculator.py) is the Waiter. It talks to the customer (you), takes your order (numbers and operation), and brings you the food (result). It doesn't cook the food itself.
  • The Backend (backend_math.py) is the Chef. It stays in the kitchen, receives orders from the waiter, performs the actual cooking (math), and hands the dish back. It never talks to the customer directly.

Part 1: The Chef (backend_math.py)

This file handles the logic. It's pure math. It doesn't know about input() or print() because the Chef doesn't talk to customers.

1. Simple Math Functions

Lines 1-4:

def add(x, y): 
    """Returns the sum of x and y."""
    total = x + y
    return total

This allows us to say add(5, 3) later and get 8 back.
Notice it uses return, not print. It gives the answer back to whoever asked for it (the specific waiter).

2. Handling Special Cases (Errors)

Lines 16-21:

def divide(x, y):
    if y == 0:
        raise ValueError("Division by Zero Error") 
    total = x / y
    return total

In math, you cannot divide by zero. If we try 5 / 0, Python will crash.
Here, the Chef checks the ingredients. If y is 0, they refuse to cook and "raise a flag" (raise an Error) saying "I can't do this!".
The Frontend will have to catch this flag later.

Part 2: The Waiter (calculator.py)

This file handles the User Interface.

1. Hiring the Chef

Line 1:

import backend_math

This import statement links the two files. It tells Python: "Hey, we are going to use the tools defined in the backend_math.py file."

2. Validating User Input (The Safety Net)

Lines 4-11:

def get_number(prompt):
    while True:
        try:
            return float(input(prompt))
        except ValueError:
            print("Invalid input. Please enter a numeric value.")

The Problem: If the program asks for a number and you type "banana", the program normally crashes.
The Solution:

  • while True: Keep asking forever until we get a valid answer.
  • try: Attempt to convert the input to a number (float).
  • except ValueError: If the conversion fails (e.g. "banana" isn't a number), don't crash! Just print an error and loop again.

3. The Infinite Loop (The Shift)

Lines 15-31:

def main():
    while True:
        # ... prints menu ...
        choice = input(...)

We want the calculator to keep running after one calculation. while True creates an infinite loop. The only way out is if the user selects the "Exit" option, which calls break to stop the loop.

4. Connecting Frontend to Backend

Lines 41-43:

if choice == '1':
    result = backend_math.add(num1, num2)

The Handover:
1. The Waiter (Frontend) has num1 and num2 from the user.
2. It calls backend_math.add(num1, num2). This passes those numbers to the Chef.
3. The Chef calculates num1 + num2 and returns the answer.
4. The Waiter stores that answer in the variable result.

5. Handling Chef's Refusal

Line 58:

except ValueError as e:
    print(f"Error: {e}")

Remember divide raising an error for zero? This except block catches that error. If the Chef says "Division by Zero Error", the Waiter catches it and politely prints "Error: Division by Zero Error" to the user instead of letting the whole restaurant burn down (program crash).
